ТЕХНИЧЕСКОЕ ЗАДАНИЕ
на разработку простого современного сайта

1. ОБЩАЯ ИНФОРМАЦИЯ

Название проекта: Nova — персональный сайт-портфолио
Тип проекта: адаптивный одностраничный сайт
Сложность: начальная / средняя
Назначение: демонстрация информации о человеке, его навыках, проектах и контактах.

Сайт должен выглядеть современно, аккуратно и профессионально, но не должен быть перегружен сложными функциями.

2. ЦЕЛЬ

Необходимо разработать готовый к использованию одностраничный сайт-портфолио.

Основные задачи:
- представить владельца сайта;
- показать его навыки;
- продемонстрировать несколько проектов;
- предоставить контактную информацию;
- обеспечить удобное отображение на ПК, планшете и телефоне.

3. ТЕХНОЛОГИИ

Разрешается использовать:
- HTML5;
- CSS3;
- JavaScript.

Дополнительно по желанию:
- Bootstrap или другой CSS-фреймворк;
- Google Fonts;
- Font Awesome / Lucide Icons.

Не требуется:
- серверная часть;
- база данных;
- авторизация;
- регистрация пользователей;
- сложная CMS.

4. СТРУКТУРА САЙТА

Сайт должен состоять из следующих блоков:

4.1. Шапка сайта (Header)

В шапке разместить:
- логотип или название «Nova»;
- меню навигации:
  - Главная;
  - Обо мне;
  - Навыки;
  - Проекты;
  - Контакты.

При нажатии на пункт меню пользователь должен плавно перемещаться к соответствующему разделу страницы.

На мобильных устройствах меню должно превращаться в компактную кнопку.

4.2. Главный экран (Hero)

На первом экране разместить:
- крупный заголовок, например: «Привет, я Алекс — начинающий разработчик»;
- короткое описание;
- основную кнопку «Посмотреть проекты»;
- дополнительную кнопку «Связаться со мной»;
- декоративный элемент или простую иллюстрацию.

Главный экран должен сразу объяснять посетителю, что это за сайт.

4.3. Раздел «Обо мне»

Разместить:
- небольшой текст о владельце сайта;
- фотографию или декоративный блок;
- краткую информацию:
  - опыт;
  - направление деятельности;
  - интересы;
  - цели.

Текст можно сделать демонстрационным.

4.4. Раздел «Навыки»

Создать карточки навыков.

Пример:
- HTML;
- CSS;
- JavaScript;
- UI/UX;
- Git;
- Figma.

Каждая карточка должна содержать название и короткое описание.

Можно добавить визуальный индикатор уровня навыка, например прогресс-бар.

4.5. Раздел «Проекты»

Создать минимум 3 карточки проектов.

Каждая карточка должна содержать:
- изображение/превью;
- название;
- краткое описание;
- использованные технологии;
- кнопку «Подробнее».

Примеры проектов:
1. Интернет-магазин;
2. Приложение погоды;
3. Панель управления.

Кнопка «Подробнее» может открывать модальное окно или вести на демонстрационную страницу.

4.6. Раздел «Контакты»

Разместить:
- заголовок;
- короткий призыв связаться;
- форму обратной связи.

Поля формы:
- Имя;
- Email;
- Сообщение;
- кнопка «Отправить».

Так как серверная часть не требуется, форма может работать в демонстрационном режиме: после нажатия отображать сообщение «Сообщение отправлено».

Также можно добавить ссылки:
- Telegram;
- GitHub;
- Email.

4.7. Подвал (Footer)

В подвале разместить:
- название сайта;
- копирайт;
- ссылки на социальные сети;
- кнопку возврата наверх.

5. ДИЗАЙН

Общий стиль:
- современный;
- минималистичный;
- технологичный;
- аккуратный.

Рекомендуемая цветовая схема:
- основной фон: тёмный;
- карточки: немного светлее основного фона;
- основной акцент: синий/фиолетовый;
- текст: белый и светло-серый.

Можно использовать:
- градиенты;
- лёгкие тени;
- скруглённые углы;
- плавные анимации;
- эффект появления элементов при прокрутке.

Важно: дизайн не должен быть чрезмерно анимированным.

6. АДАПТИВНОСТЬ

Сайт обязательно должен корректно работать на:
- компьютере;
- ноутбуке;
- планшете;
- смартфоне.

На мобильных устройствах:
- меню должно становиться мобильным;
- карточки должны перестраиваться в одну колонку;
- текст не должен выходить за пределы экрана;
- кнопки должны оставаться удобными для нажатия.

7. JAVASCRIPT

Необходимо реализовать следующие функции:
- плавная прокрутка по меню;
- мобильное меню;
- кнопка возврата наверх;
- простая валидация формы;
- сообщение после отправки формы;
- простые анимации появления элементов.

Дополнительно можно реализовать переключатель тёмной/светлой темы.

8. ТРЕБОВАНИЯ К КОДУ

Код должен быть:
- понятным;
- структурированным;
- разделённым по файлам.

Рекомендуемая структура:

/nova-site
│
├── index.html
├── css/
│   └── style.css
├── js/
│   └── script.js
├── images/
│   └── ...
└── README.txt

Необходимо использовать семантические HTML-теги:
<header>
<nav>
<main>
<section>
<footer>

CSS не должен быть полностью записан внутри HTML, если для этого нет необходимости.

JavaScript также рекомендуется хранить в отдельном файле.

9. ПРОИЗВОДИТЕЛЬНОСТЬ

Необходимо:
- оптимизировать изображения;
- не использовать слишком тяжёлые библиотеки без необходимости;
- избегать большого количества сложных анимаций;
- обеспечить быструю загрузку основной страницы.

10. ДОСТУПНОСТЬ

Необходимо:
- использовать читаемый размер шрифта;
- обеспечить достаточный контраст текста;
- добавить alt для изображений;
- сделать элементы управления доступными с клавиатуры.

11. SEO

Добавить в HTML:
- корректный <title>;
- meta description;
- viewport;
- основные meta-теги;
- понятные заголовки h1, h2 и т.д.

Пример title:
«Nova — Портфолио разработчика»

12. РЕЗУЛЬТАТ

После выполнения ТЗ должен получиться полностью рабочий сайт, который можно открыть локально через index.html.

Итоговый проект должен содержать:
- главную страницу;
- адаптивный дизайн;
- навигацию;
- блок «Обо мне»;
- блок навыков;
- блок проектов;
- контактную форму;
- footer;
- JavaScript-интерактивность;
- аккуратную структуру файлов.

13. КРИТЕРИИ ПРИЁМКИ

Проект считается выполненным, если:

[ ] Сайт открывается без ошибок.
[ ] Все основные разделы присутствуют.
[ ] Навигация работает.
[ ] Мобильное меню работает.
[ ] Сайт корректно отображается на мобильном устройстве.
[ ] Карточки проектов отображаются корректно.
[ ] Форма имеет валидацию.
[ ] После отправки формы появляется уведомление.
[ ] Анимации работают без визуальных ошибок.
[ ] Нет горизонтального скролла на мобильных устройствах.
[ ] Изображения имеют alt.
[ ] HTML/CSS/JS разделены по файлам.
[ ] Код читаемый и структурированный.

14. ДОПОЛНИТЕЛЬНЫЕ ЗАДАЧИ (НЕОБЯЗАТЕЛЬНО)

Если основная версия готова, можно добавить:
- переключатель светлой/тёмной темы;
- фильтрацию проектов по технологиям;
- модальное окно проекта;
- анимацию счётчиков;
- небольшой preloader;
- сохранение выбранной темы в localStorage.

Главное требование — дополнительные функции не должны ухудшать скорость работы и удобство сайта.
